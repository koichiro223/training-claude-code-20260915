# プロダクト要求定義書（Product Requirements）

## 0. ドキュメント情報

- 対象プロダクト：赤ちゃんの生活ログアプリ（仮称）
- 位置づけ：本アプリの**ベース機能**を定義するプロダクト要求定義書
- 前提：単一端末・単一利用者／ログイン無し／利用環境はブラウザのみ／データは端末内保存
- 具体的な設計（画面遷移・データモデル・API等）は `docs/functional-design.md` で定義する

| 版 | 日付 | 変更概要 |
| --- | --- | --- |
| 1.0 | 2026-09-15 | 初版作成。ベース機能（生活ログ／予定管理／バルーン遊び）を確定 |

## 1. プロダクトビジョンと目的

### ビジョン
赤ちゃんの毎日の生活を、保護者が「かんたんに記録し」「予定を見通せて」、さらに
赤ちゃん自身も一緒に楽しめる、あたたかい生活ログアプリを提供する。

### 目的
- 授乳・睡眠・おむつ替えなど、赤ちゃんの生活イベントを手早く記録できるようにする。
- これから行う予定（次の授乳、予防接種、健診など）を登録・確認できるようにする。
- 予定どおり実施したときは、ワンタップで実績（生活ログ）に変換できるようにする。
- 記録の合間や、赤ちゃんをあやすときに使える、シンプルで安全な遊び機能を提供する。

### スコープ外（今回作らないもの）
- 複数ユーザー／複数アカウントの管理
- ログイン・認証機能（ログイン画面は設けない）
- サーバー側でのデータ共有・同期（データはブラウザ内に保存する前提）
- 家族間での共有、外部SNS連携
- ネイティブアプリ（iOS／Android）やデスクトップアプリの提供（利用環境はブラウザのみとする）
- 統計・グラフによる高度な分析（本フェーズでは対象外。将来拡張候補）

## 2. ターゲットユーザーと課題・ニーズ

### ターゲットユーザー
- 主に乳児（0〜24か月ごろ）を育てている保護者（1台の端末を1人で利用）。
- 育児の合間に、赤ちゃんを抱っこしながら片手でも操作したい人。

### 課題・ニーズ
| 課題 | ニーズ |
| --- | --- |
| 授乳やおむつ替えの時刻を覚えていられない | ワンタップで素早く記録したい |
| 次にいつ授乳・ミルクをあげたか分からなくなる | 直近の記録をすぐ振り返りたい |
| 健診・予防接種などの予定を忘れがち | 予定を登録し、近づいたら確認したい |
| 予定どおり実施したのに、改めて記録し直すのが手間 | 予定をワンタップで実績（生活ログ）に変えたい |
| ぐずったときにあやす手段がほしい | 赤ちゃんが喜ぶ簡単な遊びがほしい |

## 3. 主要な機能一覧

1. **生活ログ記録機能**
   赤ちゃんの生活イベント（授乳・ミルク・睡眠・おむつ・お風呂・メモ など）を
   時刻とともに記録・一覧表示・編集・削除する。

2. **予定管理機能**
   これから行う予定（次の授乳、予防接種、健診、通院など）を日時つきで登録し、
   一覧・編集・削除する。近い予定を分かりやすく表示する。
   予定どおり実施した場合は、ワンタップでその予定を実績（生活ログ）として記録できる。

3. **バルーン遊び機能**
   画面上のランダムな位置にバルーンが出現し、バルーン内に数字を表示する。
   数字はカウントダウンし、0になると自動で破裂して次のバルーンが出現する。
   0になる前にタップ（クリック）できればはじけて次のバルーンが出現する。
   バルーンの色は毎回ランダムに変化する。押せた個数をカウントし、
   停止（Stop）するとその時点の押下個数と「おめでとう」メッセージを表示する。
   赤ちゃんと一緒に安全に楽しめる、単純で反応の良い遊び。

### 画面構成（概要）
本アプリはブラウザ上の単一アプリとして提供し、以下の画面で構成する。
詳細な画面遷移・レイアウトは `docs/functional-design.md` で定義する。

| 画面 | 役割 |
| --- | --- |
| トップ（ホーム） | 直近の記録と近い予定を表示し、各機能への入口を提供する |
| 生活ログ画面 | 記録の追加・一覧・編集・削除 |
| 予定画面 | 予定の追加・一覧・編集・削除、予定→実績のワンタップ記録 |
| バルーン遊び画面 | バルーン遊びの実行（開始／停止／スコア表示） |

## 4. 成功の定義

- 保護者が生活イベントを **3タップ以内** で記録できる。
- 予定どおり実施したイベントを **ワンタップ** で実績記録できる。
- 直近の記録と近い予定が、トップ画面を開いてすぐに確認できる。
- バルーン遊びが、タップに対して即座に（体感で遅延なく）反応する。
- 端末を再度開いても、記録・予定のデータが保持されている。
- ログイン等の手間なく、アプリを開いた瞬間から使える。

## 5. ビジネス要件

- 単一端末・単一利用者を前提とした、無料の個人向けツールとして提供する。
- 収益化・広告・課金は本フェーズでは対象外。
- 個人情報（赤ちゃんの氏名など）はサーバーに送信せず、端末内に留める。

## 6. ユーザーストーリー

### 生活ログ記録
- 保護者として、授乳した時刻をすぐ記録したい。授乳間隔を把握するため。
- 保護者として、記録した内容を一覧で見返したい。1日の流れを振り返るため。
- 保護者として、間違えた記録を修正・削除したい。正しい記録を保つため。

### 予定管理
- 保護者として、予防接種や健診の予定を登録したい。忘れないため。
- 保護者として、近い予定を分かりやすく確認したい。準備をするため。
- 保護者として、予定どおり実施したらワンタップで実績として記録したい。記録の手間を省くため。
- 保護者として、済んだ予定や不要な予定を削除したい。一覧を見やすく保つため。

### バルーン遊び
- 保護者として、ぐずる赤ちゃんに見せられる簡単な遊びを起動したい。あやすため。
- 赤ちゃんとして、画面をタップするとバルーンがはじけて楽しい反応がほしい。
- 赤ちゃんとして、数字がカウントダウンして0で破裂するのを見て楽しみたい。
- 保護者として、遊びを止めたときに「何個押せたか」を見て一緒に喜びたい。

## 7. 受け入れ条件

### 生活ログ記録
- イベント種別と時刻を指定して記録を追加でき、一覧に反映される。
- 記録は新しいものが上（分かりやすい順）で一覧表示される。
- 記録の編集・削除ができる。
- 端末を再度開いても記録が残っている。

### 予定管理
- 予定の内容と日時を指定して登録でき、一覧に反映される。
- 近い予定が分かりやすく（日時順、近いものを上に）表示される。
- 予定の各項目から**ワンタップ**で、その予定を実績（生活ログ）として記録できる。
  - 実績化された記録は生活ログ一覧に反映される。
  - 記録される種別・内容は元の予定を引き継ぎ、日時は実施時刻（そのタップ時刻）とする。
  - 実績化した予定は「完了」として一覧上で区別され、必要に応じて完了を取り消せる。
- 予定の編集・削除ができる。
- 端末を再度開いても予定が残っている。

### バルーン遊び
- 遊びを開始すると、画面上のランダムな位置にバルーンが出現する。
- バルーンは発生時にある程度見やすいサイズからスタートする。
- バルーン内に数字が表示され、その数からカウントダウンする。
- 数字が0になるとバルーンが自動で破裂し、次のバルーンが出現する（このときスコアは増えない）。
- 0になる前にバルーンをタップ（クリック）するとはじけ、押下個数（スコア）が1増えて次のバルーンが出現する。
- 出現するバルーンの色がランダムに変化する。
- 押せたバルーンの個数（スコア）を画面上でカウント表示する。
- 停止（Stop）すると、その時点の押下個数を表示し、
  「おめでとう XX個 おせたね」（XX＝実際に押下した個数）というメッセージを表示する。
- 過度に複雑な操作を必要とせず、単純なタップだけで遊べる。

## 8. 機能要件

### 8.1 生活ログ記録機能
- 記録できるイベント種別（ベース）：授乳（母乳）／ミルク／睡眠開始／睡眠終了／おむつ（おしっこ）／おむつ（うんち）／お風呂／体温／メモ。
- 各記録は「種別」「日時」「任意メモ」を持つ。
- 記録の追加・一覧・編集・削除（CRUD）ができる。
- 記録は日時の新しい順で一覧表示し、日付単位でまとまりを確認できる。

### 8.2 予定管理機能
- 各予定は「種別（生活ログのイベント種別に対応）」「タイトル／内容」「日時」「任意メモ」「完了状態」を持つ。
- 予定の追加・一覧・編集・削除（CRUD）ができる。
- 日時順に並べ替え、近い予定を確認しやすくする。
- **予定 → 実績のワンタップ記録**：予定を1タップで生活ログの実績として記録する。
  - 記録の種別・内容は元の予定から引き継ぐ。
  - 記録の日時は実施時刻（タップ時刻）とする。
  - 実績化した予定は「完了」状態になり、一覧上で区別できる。完了は取り消し可能とする。

### 8.3 バルーン遊び機能
- 遊び開始後、画面上の**ランダムな位置**にバルーンを1つ生成する。
- バルーンは発生時に**ある程度見やすいサイズ**（画面幅に応じた大きめの初期サイズ）からスタートする。
- バルーン内に**数字**を表示し、その数から**1カウント＝約1秒**でカウントダウンする。
  - カウントダウンの初期値はバルーンごとにランダム（ベース値：3〜5）とする。
- 数字が**0**になったら、バルーンを**自動で破裂**させ、次のバルーンを生成する（スコアは加算しない）。
- 0になる前にバルーンをタップすると、はじけるエフェクトを表示して次のバルーンを生成し、
  **押下個数（スコア）を1増やす**。
- 出現ごとにバルーンの色を**ランダム**に変化させる（あらかじめ定義した複数色から選択）。
- 押下個数（スコア）を画面上に常時表示する。
- **停止（Stop）**操作で遊びを終了し、その時点の押下個数を表示するとともに、
  「**おめでとう XX個 おせたね**」（XX＝押下したバルーンの個数）というメッセージを表示する。
- 停止後は再度開始でき、スコアは0にリセットされる。
- 記録・予定の画面とは独立した遊び専用画面として提供する。

> 注：カウントダウン初期値（3〜5）、速度（約1秒）、初期サイズ、色パレット等はベース値であり、
> 具体的な数値・色コードは `docs/functional-design.md` で確定する。

## 9. 非機能要件

### パフォーマンス
- 画面操作・バルーンのタップ反応は体感で遅延なく動作する。
- カウントダウンやアニメーションが端末に過度な負荷をかけない。

### データ保持
- 記録・予定のデータは端末内（ブラウザのローカルストレージ等）に永続化する。
- サーバーへ個人データを送信しない。
- ブラウザのデータ削除等によりデータが失われうることを前提とする（本フェーズではバックアップ機能は持たない）。

### ユーザビリティ
- 片手・タップ主体で操作できる、シンプルで大きめのUI。
- 共通のデザインシステム（Tailwind CSS）で統一感を保つ。
- 主要操作（記録追加・予定の実績化・遊びの開始/停止）に短時間で到達できる。

### 対応環境
- 利用環境はブラウザのみとする（ネイティブアプリ・デスクトップアプリは提供しない）。
- モダンブラウザ（スマートフォン・PC）で動作する。
- レスポンシブ対応（スマホ縦画面を優先）。

### セキュリティ
- 入力値のバリデーションを行う。
- 表示時のXSS対策（ユーザー入力を安全に描画）を行う。

### アクセシビリティ
- バルーン遊びは、光の激しい点滅を避けるなど、乳児が見ても過度な刺激とならない配慮をする。
- 文字サイズ・コントラストに配慮し、屋内外で見やすい表示にする。

## 10. 前提条件・制約

- 単一端末・単一利用者での利用を前提とし、認証・権限管理は行わない。
- データはブラウザのローカルに保存し、端末・ブラウザをまたいだ引き継ぎはしない。
- ネットワーク接続を前提としない（オフラインでも基本機能が動作することが望ましい）。
- 技術スタックは Next.js (App Router) / TypeScript / Tailwind CSS / npm（詳細は `docs/architecture.md`）。

## 11. 優先度（開発方針）

インクリメンタル開発の原則に従い、機能単位で段階的に実装する。ベースの実装優先度は以下とする。

| 優先度 | 機能 | 補足 |
| --- | --- | --- |
| P1 | 生活ログ記録機能 | 最も基盤となる機能。まずこれを実装・動作確認する |
| P2 | 予定管理機能（予定→実績のワンタップ含む） | 生活ログの上に積み上げる |
| P3 | バルーン遊び機能 | 記録・予定とは独立して提供 |

> 各機能の具体的な作業範囲・タスクは `.steering/[YYYYMMDD]-[開発タイトル]/` 配下で管理する。
