# ユビキタス言語定義（Glossary）

## 0. ドキュメント情報

- 対象：赤ちゃんの生活ログアプリ（ベース機能）
- 位置づけ：ドメイン用語・UI 用語を統一し、ドキュメント・コード・画面表示で一貫した語を使うための対応表。
- 使い方：新しい用語が生じたらここに追加し、コードの命名（英語）・画面表示（日本語）を本表に合わせる。

## 1. ドメインの基本用語

| 日本語 | 英語（コード名） | 定義 |
| --- | --- | --- |
| 生活ログ（記録） | LogEntry | 赤ちゃんの生活イベントを時刻とともに記録した1件の実績。 |
| 予定 | Schedule | これから行う（または行う予定だった）イベント。日時を持つ。 |
| イベント種別 | EventType | 生活ログ・予定で共通の種類（授乳・ミルク・睡眠開始/終了 等。値は §2）。 |
| 実施日時 | occurredAt | 生活ログが実際に行われた日時（ISO8601）。 |
| 予定日時 | scheduledAt | 予定が行われる（予定の）日時（ISO8601）。 |
| タイトル／内容 | title | 予定（Schedule）では必須の内容。生活ログ（LogEntry）では任意で、実績化時に予定の `title` を引き継ぐ。 |
| 測定値 | value | 数値を伴う種別（体温など）の測定値。数値。 |
| メモ | memo | 任意の自由記述（フィールド名。EventType の `memo` とは別。§6 参照）。 |
| 実績化（ワンタップ実績化） | completeAsLog | 予定を1タップで生活ログ（実績）に変換する操作。種別・内容を引き継ぎ、実施日時はタップ時刻。 |
| 完了（済み） | done | 予定が実績化された状態。 |
| 完了の取り消し | uncomplete | 実績化を取り消し、予定を未完了に戻す操作（対応する生活ログは削除）。 |
| 作成日時 | createdAt | レコードの作成日時（ISO8601）。 |
| 更新日時 | updatedAt | レコードの更新日時（ISO8601）。実績化後にログが編集されたかの判定に用いる。 |
| スコア | score | バルーン遊びで押せたバルーンの個数。 |

## 2. イベント種別（EventType）対応表

| コード値 | 日本語表示 | 補足 |
| --- | --- | --- |
| `feeding` | 授乳（母乳） | |
| `milk` | ミルク | |
| `sleepStart` | 睡眠開始 | |
| `sleepEnd` | 睡眠終了 | 開始と終了の2件で睡眠を表す |
| `diaperPee` | おむつ（おしっこ） | |
| `diaperPoo` | おむつ（うんち） | |
| `bath` | お風呂 | |
| `temperature` | 体温 | 測定値は `value`（数値）に格納 |
| `memo` | メモ | 自由記述の記録種別（EventType 値としての `memo`） |

> **`memo` の3用途に注意**：(1) EventType 値の `memo`（自由記述の種別）、(2) LogEntry/Schedule のフィールド `memo`（任意メモ）、(3) 日本語のドメイン用語「メモ」。文脈で区別する。

## 3. バルーン遊びの用語

正規のコード名は1つに確定する（表記ゆれを作らない。§6）。

| 日本語 | 英語（コード名） | 定義 |
| --- | --- | --- |
| バルーン | balloon | 画面に出現する風船。位置・色・数字・サイズ・一意IDを持つ。 |
| バルーン遊び | balloonGame（機能識別子は `balloon`、ルートは `/play`） | バルーンをタップして遊ぶ機能。 |
| カウントダウン | countdown | バルーン内の数字が減っていくこと。0 で自動破裂。 |
| 自動破裂 | autoBurst | 数字が 0 になり、タップされずに破裂すること（スコア加算なし）。 |
| 破裂（はじける） | burst | バルーンが弾けること。タップまたは自動で起こる。 |
| バルーン生成 | spawnBalloon | 次のバルーン（位置・色・カウント・ID）を生成する処理。 |
| 有効期限 | expireAt | バルーンが自動破裂する時刻。残り秒はこの時刻から算出する（時刻ベース）。 |
| 遊びの状態 | idle / playing / stopped | 未開始／プレイ中／停止後の状態機械の値。 |
| 開始 | start | 遊びを始める操作。スコアを 0 にして最初のバルーンを出す（`idle`／`stopped` → `playing`）。 |
| 停止 | stop | 遊びを終える操作。結果メッセージを表示する（`playing` → `stopped`）。 |
| 結果メッセージ | result message | 停止時に表示する「おめでとう XX個 おせたね」。 |

## 4. 画面・UI 用語

「画面呼称／ルート」列は画面の呼び名とルートパスを示す（実体は各 `page.tsx`。コンポーネント名ではない）。

| 日本語 | 画面呼称／ルート | 定義 |
| --- | --- | --- |
| トップ（ホーム） | Home（`/`） | 直近ログと近い予定のサマリ、各画面への入口。 |
| 生活ログ画面 | Logs（`/logs`） | 記録の一覧・追加・編集・削除。 |
| 予定画面 | Schedules（`/schedules`） | 予定の一覧・追加・編集・削除・実績化。 |
| バルーン遊び画面 | Play（`/play`） | バルーン遊びの実行。 |
| クイック記録 | quickLog | よく使う種別をタップして現在時刻で即記録する操作。 |
| 空状態 | empty state | データが0件のときに表示する案内。 |
| 確認モーダル | confirm modal | 削除・完了取り消しなど破壊的操作の確認ダイアログ。 |
| 近い予定 | upcoming schedules | 未完了予定を `scheduledAt` 昇順で表示したもの。 |
| 遅れ | overdue | 未完了かつ `scheduledAt` が現在時刻より過去の予定。近い予定の中で区別して表示する。 |

## 6. 命名の原則

- コード上の英語名は本表の「英語（コード名）」に合わせ、1用語1コード名とする（`feed`/`feeding` のような表記ゆれや、`burst`/`pop` のような併記を作らない）。
- 画面表示の日本語は本表の「日本語」に合わせる。
- 新語が必要になったら、実装前に本表へ追加し、日本語・英語・定義をそろえる。
- 詳細な命名の書式（PascalCase/camelCase 等）は `docs/development-guidelines.md` を参照。
