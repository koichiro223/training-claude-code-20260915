# 要求内容 — 予定管理機能（P2）

## 0. この作業バッチの位置づけ

- 作業バッチ名：`20260915-schedule`
- 対象：予定画面（`/schedules`）の実装。予定の追加・一覧・編集・削除、および**ワンタップ実績化**・完了取り消し。
- 依存：**`20260915-foundation` 完了が前提**（型・`useSchedules`（`completeAsLog`/`uncomplete` 含む）・共通UI・lib を利用）。
- 並行性：foundation 完了後は life-log / balloon-game と**独立して並行開発可能**。実績化のドメインロジック（`buildLogFromSchedule`）と logs+schedules の同時更新は foundation 側に実装済みで、本バッチは UI から `completeAsLog`/`uncomplete` を呼ぶのみ。

## 1. 変更・追加する機能の説明

予定画面（`/schedules`）を構築する。`docs/functional-design.md` 3.3・4.2 準拠。

- **予定追加フォーム**：種別／タイトル（必須）／日時／メモ。
- **一覧**：未完了を `scheduledAt` 昇順、続けて完了を後方（完了は `scheduledAt` 降順）。未完了/完了をスタイルで区別。
- **ワンタップ実績化**：各未完了予定の「実績にする」ボタンで `completeAsLog` を呼ぶ。
- **完了取り消し**：完了予定を `uncomplete` で未完了に戻す（確認モーダル、ログ編集済みなら警告）。
- **編集・削除**：各項目を編集・削除（削除は確認モーダル）。
- **空状態**：0件時に追加を促す。

## 2. ユーザーストーリー

- 保護者として、予防接種や健診の予定を登録したい（忘れないため）。
- 保護者として、近い予定を分かりやすく確認したい（準備のため）。
- 保護者として、予定どおり実施したらワンタップで実績記録したい（記録の手間削減）。
- 保護者として、済んだ/不要な予定を削除・取り消ししたい（一覧を見やすく保つ）。

## 3. 受け入れ条件

- 種別・タイトル・日時を指定して予定を追加でき、一覧に反映される。
- 一覧は未完了が `scheduledAt` 昇順で上、完了は後方に区別表示される。
- 未完了予定の「実績にする」で**ワンタップ**実績化でき、生活ログに反映される（種別・タイトル・メモ引き継ぎ、日時=タップ時刻）。
- 実績化済み（`done=true`）予定には「実績にする」ボタンを表示しない（二重実績化防止）。
- 完了予定を「完了を取り消す」で未完了に戻せる。取り消しは確認を挟み、対応ログが実績化後に編集されている場合はその旨を明示して確認する。取り消し時は対応 LogEntry を削除する。
- 予定の編集・削除ができる。削除は確認モーダルを挟む。
- 端末を再度開いても予定が残っている。
- 0件時に空状態メッセージを表示する。
- `npm run lint` / `npx tsc --noEmit` がエラー・警告なしで通る。

## 4. 制約事項

- 状態・永続化・実績化ロジックは `useSchedules()` 経由のみ。logs+schedules の同時更新・参照整合性は foundation が担保（本バッチで独自に logs を書かない）。
- 型は `@/types`、日時は `@/lib/datetime`、定数は `@/lib/constants`、確認モーダル・通知・空状態は `@/components/ui` を使う。
- バリデーション：タイトル必須・トリム・最大100文字、日時必須・パース可能（過去日時許容）、メモ最大500文字。
- ページ（`app/schedules/page.tsx`）は薄く保ち、UI 実体は `components/schedules/` に置く。
- XSS 対策（`dangerouslySetInnerHTML` 不使用）。
- Git 操作は行わない。
